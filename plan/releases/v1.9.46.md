## Highlights

**`SESSION_OP` works against the FlightDesk that actually shipped.** FlightDesk merged its
orchestration streams (#115–#118, CLI 0.5.0) after v1.9.45 was built. Checking Qalatra's poller
against that code rather than the plan found two mismatches that would have broken session
operations on first use, both fixed here:

- FlightDesk stores the op spec in `sessionOp` and the *rendered* inject text in the request's
  own `prompt`; Qalatra only looked inside the spec, so every inject would have been refused as
  "requires a rendered prompt".
- FlightDesk's report schema takes optional strings and rejects `null`, so a `state` read with
  no transcript (`lastTurnAt: null`) would have been refused. Reports are now compacted before
  sending.

Confirmed unchanged and compatible: the dispatch list query, the legacy `qalatraJobId` alias,
the `REQUESTED → DONE | FAILED` shortcut for `SESSION_OP`, `resumeSession` / `taskUrl` /
`preambleVersion` on each request, the CLI's outbox file format, and that FlightDesk's rendered
prompt expects Qalatra to append the `## Answers` block.

## Verification

`scripts/test-flightdesk-dispatch.mjs` now exercises FlightDesk's real `SESSION_OP` request
shape (spec in `sessionOp`, prompt beside it) and asserts that null fields never reach a report.
49 assertions pass.
