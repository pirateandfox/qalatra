## Highlights

**Routine MCP reads use dramatically less context.** `search_tasks`, `get_tasks_by_agent`,
`list_agent_jobs`, and `get_agent_job` now return compact operational fields by default instead of
silently including full descriptions, AI history, prompts, and results. Callers can request any
specific projection or pass `fields: "*"` when the complete record is genuinely needed. Measured
20-row responses were 82% smaller for task searches and 89% smaller for agent-job listings.

**MCP usage is measurable without exposing task content.** Structured server logs now record each
tool's duration, argument/result byte counts, returned-item count, and error code, but never the
arguments or results themselves. Agent jobs also retain provider-reported input, output, and cache
token counts plus the number of Qalatra MCP calls visible in the runtime event stream.

**Definition and serialization overhead is lower.** MCP results are emitted as compact JSON, verbose
repeated schema guidance was shortened, and the server advertises concise instructions that help
Claude Tool Search discover Qalatra tools without eagerly loading every definition. The tool schema
surface is about 7% smaller. No restricted MCP profile was added; every existing connection receives
the same safer defaults and remains capable of requesting complete records.
