## Highlights

**Agent jobs are no longer tied to one CLI.** Prompt-mode agents were hard-wired to Claude Code's
command line in three separate places — the argv, the parsed output shape, and the session-id resume
model — even though the capability registry already advertised `provider_support: ["claude",
"codex"]`. Nothing in the runner read that field. A new adapter layer (`server/agent-runtimes.js`)
supplies argv construction and output parsing per runtime, and `agent.config` accepts a `runtime`
field: `claude` (default), `codex`, or `raw`. Everything else in the pipeline — environment, spawn,
timeouts, output rules, job lifecycle — was already provider-neutral and is untouched.

Existing configs are unaffected. An absent `runtime` resolves to `claude`, template-mode commands
still run verbatim, and an unrecognised runtime logs a warning and falls back rather than failing
the job.

**A timed-out agent no longer loses its work.** `--output-format json` emits only when the process
exits, so killing a job discarded its session id along with it and the run could not be continued.
Agent output is now consumed incrementally, and because every Claude stream-json event carries
`session_id`, the id is captured within moments of launch. A job killed nine seconds in resumed
cleanly with the agent still aware of its original task.

Timeouts became their own terminal status, `timed_out` (`terminated_by = 'timeout'`), alongside
`orphaned` — Qalatra's own resource limits no longer inflate agent failure counts. The resume lookup
accepts these jobs, so the next message on the task continues where the agent left off, and the
result names the limit that was hit, flags the session as resumable, and carries any partial output.

**Killing an agent now kills what it started.** A timeout signalled only the tracked process. That
pid really is the agent — the login shell `exec`s through to it — but the agent's own children were
reparented and survived, leaving a test run, a build, or an MCP server running unsupervised after
Qalatra had already declared the job dead and freed its concurrency slot. Agents now run in their
own process group and timeouts take the whole group down. Because that also escapes the signal a
service manager sends to Qalatra, shutdown terminates live agents explicitly rather than stranding
them across a restart.

## Changes worth knowing

- The default job timeout moved from 15 to 60 minutes. Fifteen was too tight for a modern coding
  agent; a hung job still holds one of only three concurrency slots, so it stays bounded. Per-agent
  `timeout_minutes` continues to win.
- New opt-in `idle_timeout_minutes` kills a job after N minutes with no output at all. A wall clock
  cannot distinguish a productive fifty-minute run from one wedged after ninety seconds; streamed
  output can. Off by default, because a single long tool call legitimately emits nothing for a while.
- `"stream": false` in `agent.config` falls back to the previous single-blob output format without a
  code change.
- Output buffering is now bounded — a session id, the final result and a 64 KB tail, with stderr
  capped at 256 KB — instead of accumulating every byte of a long run.
- Jobs record which runtime ran them and show it in the detail panel. The "Resume session" buttons
  previously emitted `claude --resume` for every job regardless of runtime, and now emit
  `codex resume` for Codex jobs.
- The `list_agent_jobs`, `get_agent_job` and `get_tasks_by_agent` MCP tools document `orphaned` and
  `timed_out` and state plainly that neither is an agent failure, so an agent reading job outcomes
  branches on them correctly instead of treating a resumable timeout as a hard failure.

## Verification

Adapters were built against captured output from the real CLIs rather than assumed behaviour, which
caught two mistakes worth noting: Codex takes its prompt positionally (its `-p` is `--profile`, not
print), and `codex exec resume` accepts only a subset of `codex exec`'s flags and hard-errors on the
rest, which failed every resumed turn until the adapter began filtering them.

Beyond unit coverage, the release was exercised end to end against a real server on an isolated
database and port: the new column migrated onto an existing schema, a Claude job and a Codex job both
completed with their runtime and session id recorded, a job hit its timeout and landed as `timed_out`
with a resumable session, and a follow-up on that task resumed the same session with the agent still
aware of its original instruction. Process-group kills were measured to reap an agent together with a
subprocess it had spawned, in both prompt and template mode, with the job lifecycle still completing
normally afterwards.
