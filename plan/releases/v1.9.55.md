## Highlights

**Agent folders can run different tasks in parallel (opt-in).**

- With `"worktrees": true` in `agent.config`, each task-bound job (for example a FlightDesk
  dispatch) runs in its own git worktree under `<repo>/.qalatra-worktrees/<task>`. Different tasks
  in one folder now run side by side up to the three-job limit; jobs for the same task still run
  one at a time. Folders that don't opt in behave exactly as before.
- The worktree starts from the repo's base branch (dispatch, `worktree_base`,
  `agents/pipeline-config.md`, then `origin/HEAD`), is reused for the task's later jobs so sessions
  resume, and is removed when the task closes or after 7 idle days. Identity and `.flightdeskrc`
  still come from the bound folder. If a worktree can't be prepared the job fails as
  `launch_failed` rather than falling back to the shared folder.
- Tasks that already have a session from the folder finish there. FlightDesk stage prompts must
  stop running `git checkout <base>` before a folder opts in.

**Per-agent memory limits, and out-of-memory kills are reported as such.**

- `memory_high` / `memory_max` in `agent.config`, or `agentMemoryHigh` / `agentMemoryMax` in
  settings for a whole box, set each run's cgroup limits (default stays 1G/2G). Invalid values are
  logged and ignored; launch diagnostics show the limits in effect.
- A run killed by its memory limit is now recorded with `terminated_by = 'oom'` and a clear
  message instead of a bare failure, and its session can be resumed. FlightDesk receives it as an
  `error` with the OOM explanation first.

**Dependency security updates.** Electron downloads during packaging now use `@electron/get` 5,
the UI's single-file builds use a local plugin (identical output), and several transitive
packages were updated to patched releases.
