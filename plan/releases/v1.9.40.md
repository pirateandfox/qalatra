## Highlights

**Unsafe template-command quoting is now visible before it causes a silent prompt truncation.**
Qalatra already consumes an author's exact `'{description}'`, `"{description}"`, `'{title}'`, or
`"{title}"` wrapper and replaces the whole expression with one shell-quoted value. The compatibility
fallback for bare placeholders could also fire when text had been appended inside an author's
still-open quote. That nested an already-quoted value inside the remaining quote and could reduce a
multi-word cloud-agent prompt to its first bare word.

Template launch now warns with the job id when the bare fallback finds a quote immediately before a
placeholder without the matching quote immediately after it. Exact quote-delimited placeholders and
genuinely bare placeholders continue to work unchanged.

**Failed-job diagnostics show what the shell actually received.** Launch diagnostics previously
included only the unresolved command template, which hid substitution failures and forced operators
to reconstruct the executed string by hand. They now include the sanitized resolved template command
alongside the sanitized source template. Existing token, secret, credential-URL, and sensitive flag
redaction applies to both lines.

**Dependency maintenance since 1.9.39 is included.** Root and mobile lockfiles were refreshed to
clear every currently patchable advisory. The mobile audit continues to allow only its three narrow,
documented build-tool/deep-link exceptions; no mobile artifact is published by this release.
The release toolchain also moves to electron-builder 26.16.1, whose macOS fix supplies
`set-key-partition-list` with the temporary keychain's password rather than the imported certificate
password. This restores signing on the macOS 25.6 GitHub runner image.

## Verification

New command-template regression coverage reproduces the original malformed substitution, including
the resulting `''Execute the plan'` shell fragment. It also verifies that exact single-quoted,
double-quoted, and bare placeholders retain their existing behavior, that malformed title and
description forms emit warnings, and that resolved diagnostics redact secrets.

The full pre-publish gate passed locally: root and UI audits, the documented mobile audit, import
checks, shared and mobile typechecks, account and server suites, headless server smoke test, UI build,
and UI lint. A scan of 98 locally available fleet `agent.config` files found no remaining malformed
quoted title or description placeholders. The longer-term move from shell strings to structured
executable/argv templates is tracked in GitHub issue #2.
