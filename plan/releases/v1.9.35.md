## Highlights

**MCP clients recover automatically after a server restart.** The MCP HTTP server keeps its session
table in memory with no expiry, so every Qalatra release — which restarts the server — forgets every
live session. A client reconnecting afterwards presented a well-formed id for a session that no
longer existed, and the server answered `400 Bad Request`. That conflated "your session is gone,
re-initialize" with "your request is malformed", so clients surfaced an error instead of recovering,
and a routine release looked like a session expiry.

An unknown-but-present session id now returns `404` on POST, GET, and DELETE, which is the status
the Streamable HTTP spec defines as "start a new session with a fresh InitializeRequest". A missing
id on a non-initialize request still returns `400`. DELETE of an already-gone session returns `404`
rather than an error, since that is already the caller's desired end state.

Verified end to end against a local server: initialize → use → restart → the same id returns `404` →
re-initialize yields a new id. Malformed requests still return `400`.

## Notes

No schema, API surface, or UI changes. Restart Claude Code only if a client was left in a stuck
state from a prior release; new sessions recover on their own.
