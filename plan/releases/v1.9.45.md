## Highlights

**FlightDesk can now drive agent work, pull-only, with Qalatra as the executor.** FlightDesk
decides *when* an agent should run and records it as a dispatch request; Qalatra Server polls for
those on its 30-second tick, turns each into an agent job, and reports the job's lifecycle back.
Nothing calls into a box — the only traffic is outbound HTTPS — and the poller is code, so an
empty poll costs no model tokens. This replaces the 15-minute watcher agent that discovered work
by reading everything, without requiring anyone to retire it: existing pipelines keep running
exactly as they do today, and a folder only takes part when it holds its own `.flightdeskrc`.

- **FlightDesk is an integration, not a dependency.** Standalone Qalatra runs identically with no
  FlightDesk code active. The core gained a generic orchestration surface — `queueExternalJob`
  (an orchestrator's prompt stored verbatim, idempotent on `external_ref`), `resume_session` per
  job, `tasks.orchestrator`/`orchestrator_ref` (who *drives* a task, distinct from where it was
  born), and `onJobStarted` / `onJobFinished` / `orphanedAtBoot` hooks with diagnostics kinds
  (`error | timed_out | orphaned | launch_failed | dependency_down`). FlightDesk is the first
  consumer, in `server/integrations/flightdesk/`.
- **Lifecycle reporting that survives outages.** FlightDesk's status ladder cannot step
  backwards, so reporting walks it to the target and treats "already past that" as success: a
  lost ack, a lost RUNNING, or a restart between steps reconciles on the next poll. Finishes carry
  an 8 KB result tail, the full length, and whether the session is resumable; jobs running when
  the server restarted are reported `FAILED / orphaned` at boot. One Qalatra task per FlightDesk
  task; `RESUME` dispatches consume the frozen human answers server-side and append an
  `## Answers` block headed by a treat-as-data line.
- **Session operations without an agent.** Relaying "CI failed on PR #12", nudging a rebase,
  clicking Create PR, archiving after merge, or reading whether a cloud session ended asking a
  question needs no judgement. FlightDesk asks for these as `SESSION_OP` dispatches and Qalatra
  Server performs them through claude-bridge (`server/session-ops.js`) inline on the tick — no
  job, no tokens. An inject requires a FlightDesk-owned template id and counts as done only when
  the bridge verified it landed in the intended session; every executed op is recorded so a
  re-delivered request is answered, never run twice; ops wait while an agent holds the folder;
  an unreachable bridge or a disconnected Chrome reports `dependency_down`.
- **Outbox replay.** When the FlightDesk CLI cannot reach FlightDesk from inside a job, it writes
  the GraphQL it failed to send to `<folder>/.flightdesk-outbox/`; each poll replays those files
  in order, moving deterministic rejections aside and keeping transport failures for next time.
- **Settings → Integrations** shows each bound folder's last poll, last success, errors, and
  counts, with a Poll-now button. `GET /api/v1/integrations` exposes the same.

**At most one job runs per agent folder at a time.** Every job in a folder shares that folder's
working tree, so two at once fight over one checkout — and after a restart or an outage the whole
backlog arrives together, which made this the normal case rather than an edge. `getQueuedJobs`
now serializes per concurrency key (`agent.config` `concurrency_key`, defaulting to the folder);
a repo that splits `plan/`, `execute/` and `pipeline/` over one checkout gives them the same key.
The previous-session lookup also breaks same-second ties so the latest session always resumes.

## Verification

`scripts/test-flightdesk-dispatch.mjs` drives `db-worker.js` as a real worker thread against a
fake FlightDesk that enforces the real transition rules — 48 assertions across queue, re-delivery,
lifecycle, lost ack, timeout, blocked tasks, RESUME answers, ordering, `resume_session`, restart
orphans, ghost acks, 401, session ops (verified, unverified, missing template, deferred, bridge
down, ledger replay) and outbox replay. `scripts/test-job-concurrency.mjs` covers the per-folder
lock. The session-ops client was exercised against the live claude-bridge daemon on macOS, and the
server was booted with API, MCP and workers enabled with no bound folders to confirm the
integration is inert by default. Design record: `flightdesk/docs/2026-09-17-orchestration-plan-shared.md`.
