## Highlights

**The MCP endpoint now belongs to the current Qalatra Server generation.** Parent-managed MCP
children use an IPC channel that closes if the parent exits or is killed by the OOM killer. The
child exits on that disconnect, so an older generation can no longer remain alive indefinitely and
silently retain port 3457.

MCP startup now happens only after the API server acquires port 3456, Qalatra's single-instance
lock. A duplicate API process therefore cannot create an unauthoritative MCP child. The child also
acknowledges its successful bind over IPC; `/health` stays non-2xx until that exact child is ready
and reports its PID, status, restart count, consecutive startup failures, and last error.

Port conflicts are no longer retried forever. Parent-managed children fail their bind immediately,
the parent applies bounded exponential backoff, and five consecutive startup failures terminate
the server visibly. Graceful shutdown cancels pending restarts and reaps the child with bounded
disconnect and kill fallbacks.

## Existing Linux installations

Children created by 1.9.35 or earlier do not have the new IPC tether and must be removed once after
upgrading. Run this from the updated checkout as the Qalatra service user:

```bash
bash scripts/remediate-orphaned-mcp.sh
```

The script stops `qalatra-server.service`, terminates only same-user processes whose argv exactly
matches that checkout's MCP entry file, verifies port 3457 is free, restarts Qalatra, waits for MCP
readiness, and confirms the sole MCP PID is a direct child of the current systemd `MainPID`. It
does not kill tmux or agent jobs.

## Verification

Regression coverage now proves that a parent `SIGKILL` releases the MCP child and port, a process
that loses the API single-instance lock never starts MCP, an occupied MCP port produces red health
and a bounded nonzero parent exit, and graceful shutdown leaves no child behind.
