## Highlights

**A recurring agent task no longer stops autorunning after one unfinished run.**

- Autorun skipped any task that had ever had an agent job. A recurring task only moves to its next
  occurrence when it is completed, so a single run that was killed before finishing (for example
  by the timeout) left the task active with one job, and autorun never started it again, with no
  error anywhere.
- A recurring task is now held back only by a job that is still queued or running, or one already
  started today. An unfinished occurrence is retried once a day at its autorun time until it is
  completed. One-off tasks still autorun only once.
- After upgrading, a recurring autorun task that was stuck this way starts at the next autorun
  check (within about five minutes) if it is due and its autorun time has passed.

**The Terminals agent list works again when an agent.config uses the array form of `command`.**

- An `agent.config` with `"command": [ ... ]` made every agent scan fail with "SQLite3 can only
  bind numbers, strings, bigints, buffers, and null", so Terminals and Settings → Agents showed
  no agents. The array is now stored as text, as it already was for the agents list itself.
- Scan failures at server start are now logged instead of being silently ignored.

**Worktree and concurrency decisions follow agent.config as it is on disk.**

- Whether a job runs in its own worktree, and which concurrency key it uses, came from a copy of
  agent.config that was refreshed only at server start or when the agents screen was opened. A
  folder that turned on `worktrees: true` kept running tasks in its main checkout until the next
  restart, and a task that started there stayed there, leaving the main checkout on a task branch.
- Before starting queued jobs, Qalatra now re-reads the agent.config of each folder that has
  queued jobs, so a change takes effect on the next job without a restart.

**File links open on every machine.**

- A link can be written relative to the workspace root, such as `projects/shi/desk.md`, and opens
  wherever that workspace lives: `~/IdeaProjects` on a laptop, `~/workspaces` on a server.
- Existing absolute links written on the other machine (`/Users/<name>/IdeaProjects/...` or
  `/home/<name>/workspaces/...`) are translated to this machine's workspace when the original path
  does not exist here, so older links keep working. Paths outside the allowed folders are still
  refused.
- The MCP `create_task` and `update_task` tools now ask agents to write workspace links in the
  relative form.

**Dependency security updates.**

- `hono` (through the MCP SDK) 4.13.8 → 4.13.13, the UI's `vite` build tool 8.0.16 → 8.3.4, and
  the mobile app's `markdown-it` 14.3.2 → 14.3.3, each for a newly published advisory.

## Verification

- `npm run pre-publish` passes (audits, build, typechecks, lint, `ci:server`), along with `test:worktrees`, `test:job-concurrency`,
  `test:job-scheduler`, `test:agent-restart`, `test:flightdesk-dispatch` and `test:session-ops`.
- The autorun query was checked against an in-memory database: a recurring task whose only job
  timed out on an earlier day is picked up; one with a job today, or a running job, is not; a
  one-off task that already ran is not.
- An agent folder with an array `command` reproduced the scan error before the fix and scans
  cleanly after it.
- Re-reading a folder's agent.config flips a stale `worktrees` and concurrency key in the agents
  table while keeping its folder and relative path.
- File path resolution: relative, laptop and server paths all resolve to the same local file, a
  new relative file lands under the workspace root, and `/etc/passwd` and `..` escapes are refused.
