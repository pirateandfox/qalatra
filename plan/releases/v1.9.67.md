## Highlights

**Agent jobs no longer run with the server's `NODE_ENV=production`.**

- Qalatra Server's service file sets `NODE_ENV=production`, and every agent job inherited it. On
  every box, an agent's `npm install` silently skipped devDependencies, and its tests, builds and
  dev servers ran in production mode without anyone choosing that.
- Jobs now start without the server's `NODE_ENV`. The server itself still runs in production mode.
  A box or folder that wants a value sets it in `agentEnv` (settings) or `env` in `agent.config`,
  and that value is passed through as before.
- `ELECTRON_RUN_AS_NODE`, which the desktop app sets on its server, is dropped the same way, so an
  Electron app started by an agent on the Mac runs as Electron rather than plain Node.
- Per-folder workarounds such as `"NPM_CONFIG_INCLUDE": "dev"` in `agent.config` keep working and
  are no longer needed.

## Verification

- `test:flightdesk-dispatch` checks that a job does not get `NODE_ENV` or `ELECTRON_RUN_AS_NODE`
  from the server, and that a `NODE_ENV` configured in `agentEnv` still reaches it.
- `npm run ci:server` passes.
