## Highlights

**A cloud session that stops and asks for work is noticed, not just one that asks a question.**
When a cloud session needs something only the box can do — run a migration, install a dependency,
set a secret — it stops and says so. FlightDesk turns that into a turn for the repo's management
agent, which pulls, migrates, regenerates, pushes and tells the session to continue, exactly as
today's monitor does. Qalatra's session read decided "asked for something" by a trailing question
mark alone, so the most common phrasing (*"I need the migration run and pushed before I can
continue."*) would have fallen through to the age ceiling, which surfaces a task but never
re-dispatches it.

- The last turn is now also read for request phrasing in its closing paragraph — *please, I need,
  let me know, waiting for, blocked on, run the migration, before I can continue* — capped to the
  closing paragraph so an incidental "please" in a long summary does not match.
- `state` additionally reports `sessionIdle`: the session is `ready`, its worker is idle, and the
  last word was the assistant's. `unknown` is never idle, per the bridge's contract. FlightDesk can
  key on this directly once it accepts the field.
- The migration turn itself is unchanged: same folder, same command, same permissions as the
  current pipeline agent. Only the trigger differs.
