## Highlights

**A missed recurring task stays until it's done.**

- Before, a recurring task whose due date had passed was marked skipped and replaced by its next
  occurrence as soon as Today loaded or the morning briefing ran, whether or not the work had been
  done. That suits routines, not work: an agent's weekly task could be closed out unseen.
- Now a missed occurrence stays active, and shows as overdue, until someone completes or skips it.
  The next occurrence is created only then, dated today or later, so finishing something weeks late
  doesn't create one that is already overdue.
- This applies to every existing recurring task. For tasks that should still move on by
  themselves, such as daily routines, set **If missed: Skip to next** in the task's detail panel,
  or `missed_occurrence: "skip"` through MCP `create_task`/`update_task` or the API. The setting
  carries to later occurrences.
- A task skipped automatically no longer counts as touched by a person, so it no longer appears in
  "Done today".
- Context is not copied between occurrences.

**Recurring occurrences can be followed by series.**

- Each new occurrence records its series (`series_id`, the id of the occurrence it started from).
  `get_task` on a finished occurrence returns `current_occurrence_id`, and `search_tasks` accepts
  `series_id`, so an agent holding an older occurrence's id can find the current one.
- Existing chains start carrying a series id from their next new occurrence; earlier ones are not
  linked.

**Tasks with only a start date show on that date when you look ahead.**

- A task with a future start date and no due date is hidden from Today until it starts, and the
  view of a future day only listed tasks due that day, so it appeared on no date at all. It is now
  listed on its start date.
