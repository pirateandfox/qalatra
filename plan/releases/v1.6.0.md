# Qalatra 1.6.0 - Remote instances, trust signals, and Agent IDE

This release turns Qalatra into a server/client system that can run on a dedicated Linux box while the desktop app connects to it remotely. It also adds the first Agent IDE surfaces for working directly inside those boxes, plus task trust signals that make the priority list easier to scan.

## Highlights

- Added Qalatra Server, an authenticated headless HTTP API that owns SQLite, MCP startup, background workers, agent jobs, heartbeats, attachments, backups, tokens, and encryption-key access.
- Added Settings -> Instances so the desktop app can switch between the local server and saved remote Qalatra servers.
- Added Linux headless bootstrap and service scripts for dedicated agent boxes, including systemd user service support and optional Cloudflare Tunnel setup.
- Added built-in Agent IDE surfaces: persistent tmux-backed terminal sessions and a separate workspace file browser/editor.
- Added trust signals for tasks: hard deadlines, stale-review indicators, and blocking relationships.
- Added a capability registry and richer agent metadata so Qalatra can understand what registered agents are for.
- Cleaned up task rows by removing attachment/link chip clutter from the list view while keeping those details in the task panel.

## Qalatra Server and Remote Instances

- New server runtime under `server/` listens on port `3456` by default.
- `/health` is available without auth for uptime checks.
- API routes under `/api/v1` are token-authenticated with `Authorization: Bearer <token>`.
- Bootstrap creates an initial admin token at `~/.local/share/qalatra/db/admin-token.txt` on headless installs.
- Tokens can be listed, created, revoked, and given optional expiration dates.
- The Electron app now talks to the same HTTP API path used by remote clients.
- Settings -> Instances can connect to remote URLs, save bearer tokens, and manage the local server lifecycle.
- The temporary `/api/rpc` bridge is removed.

## Linux Headless Server

- Added `scripts/bootstrap-linux-server.sh` for one-line Debian/Ubuntu installs.
- Added `scripts/install-linux-server.sh` for idempotent install/update of the user systemd service.
- Added `scripts/install-cloudflare-tunnel.sh` for a Qalatra-only Cloudflare Tunnel service.
- Added `scripts/rebuild-node-native.mjs` so `better-sqlite3` and `node-pty` are rebuilt for system Node on Linux.
- The installer now verifies `tmux`, creates `~/workspaces` by default, and seeds workspace settings on first install.
- The installer now refreshes npm dependencies on every run, which makes existing headless boxes safe to update when releases add server dependencies.
- MCP stays local on port `3457`; do not publish the MCP port through Cloudflare.

## Agent IDE

- Added a Terminals view with persistent tmux-backed sessions.
- Terminal sessions can survive client disconnects and be reattached later from the Qalatra UI.
- New terminal sessions can start from a registered agent, using the agent's context, project, configured path, and display name.
- The agent picker is searchable by context, project, and agent name, and sorted by context first, then project, then agent.
- Added a separate Files view for browsing registered workspaces and editing text files.
- File APIs enforce registered workspace roots and support remote text read/write through the authenticated API.

## Trust Signals

- Added `hard_deadline` to tasks. A hard-deadline due date is visually distinct in the list and available through MCP/API create and update flows.
- Added `last_reviewed_at` to tasks. New tasks initialize it, human updates refresh it, and tasks can be explicitly marked reviewed.
- Added stale-task detection with default active/backlog review windows and MCP support via `get_stale_tasks`.
- Added `task_dependencies` so tasks can be blocked by other tasks instead of relying on freeform text.
- Added MCP tools to add, remove, and inspect dependencies.
- `get_task` and task-list responses now include blocked state and dependency summaries.
- The UI de-emphasizes blocked or stale work and surfaces dependency details in the task panel.

## MCP and Agent Workflow

- Added task trust-signal support to MCP create/update/read tools.
- Added `mark_reviewed`, `get_stale_tasks`, `add_dependency`, `remove_dependency`, and `get_dependencies`.
- Added capability registry tooling for registering, listing, updating, and discovering agent capabilities.
- Added daily-note search memory support so agents can find relevant historical notes more reliably.
- Added automatic attachment recovery for local files mentioned in agent comments, even when the agent did not explicitly attach the file through MCP.
- Verified direct MCP daily-note access after server restart; if an existing AI client has a stale MCP session, restart that client so it reconnects to the current server process.

## UI Changes

- Added Hard deadline controls to the task detail panel and task creation flow.
- Added Reviewed status and Mark reviewed controls to the task detail panel.
- Added dependency display in the task detail panel for "Blocked by" and "Blocking" relationships.
- Removed bulk attachment/link chips from the task list row to prevent crowded rows when a task has many attachments.
- Kept attachments and links in the task detail panel, where they are actionable.
- Added source indicators for tasks when a source can be identified without showing every linked item.

## Updating Linux Headless Boxes

Desktop apps receive this through the normal auto-updater. Headless Linux installs update from the git checkout:

```bash
cd ~/qalatra
git fetch origin develop --tags
git checkout develop
git pull --ff-only origin develop
./scripts/install-linux-server.sh
systemctl --user restart qalatra-server.service
curl -fsS http://127.0.0.1:3456/health
```

Then smoke test the authenticated API:

```bash
TOKEN=$(cat ~/.local/share/qalatra/db/admin-token.txt)
curl -fsS -H "Authorization: Bearer $TOKEN" http://127.0.0.1:3456/api/instance
```

If the box uses Cloudflare Tunnel, also check:

```bash
systemctl --user status qalatra-cloudflared.service --no-pager -l
```
