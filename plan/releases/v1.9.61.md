## Highlights

**Running agent jobs are re-adopted after a server restart on Linux.**

- 1.9.60 left agent runs going across a restart, but the restarted server still reported them
  orphaned. Runs were launched with their state files under the system temp directory, while boot
  recovery looked under the data directory and found nothing. The agent kept working while Qalatra
  and the orchestrator treated the job as lost.
- Runs are now launched under the data directory, where recovery looks, so a live run is picked
  up again and finishes through the normal path.
- The update that installs 1.9.61 is still a 1.9.60 restart, so jobs running at that moment are
  orphaned. Restarts after that keep them.

## Verification

- `test:agent-restart` and the worker lifecycle and job scheduler suites pass.
- On a Linux box running 1.9.60, the previous instance logged that it was leaving the run for
  re-adoption and the agent outlived the restart, but the new instance orphaned the job. Its run
  directory was under `/tmp/qalatra/agent-runs/` rather than the data directory.
