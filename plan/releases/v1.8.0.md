# Qalatra 1.8.0 — Time estimates, smarter briefings, and events that take care of themselves

This release is about knowing what your day actually costs. You can now attach time estimates to tasks and see a live capacity summary right in the today view. Briefings got smarter about what they surface — reading tasks no longer pollute your operational queue. And calendar events now clean themselves up when they're over.

## Highlights

- Added `time_estimate` to tasks — store how long something will take in minutes, see it as a badge on every task row.
- Added a capacity banner to the today view — instantly see total estimated time and how many tasks have no estimate yet.
- `morning_briefing` MCP tool now returns a `capacity` object: estimated minutes, tasks with estimates, and tasks without, across everything due today.
- Reading-lane tasks (`task_type: reading`) are now excluded from all operational briefing outputs so agents stop confusing reading items with actionable work.
- Past events and timed events that have ended now auto-complete — they clear off the today view without any manual action.
- Added a ✓ done button directly on event cards for manual completion when needed.

## Time Estimates and Daily Capacity

A new `time_estimate` field (stored in minutes) is available on every task.

- **Detail panel**: pick from preset chips — 15m, 30m, 1h, 1.5h, 2h, 4h. Click the active chip to clear it.
- **Task row**: shows a `⏱ Xh Ym` badge next to the energy indicator when an estimate is set.
- **Today view**: a capacity banner appears above the task list — "⏱ 5h 30m estimated + 8 unestimated" — so you can see at a glance how loaded the day is.
- **MCP**: `create_task` and `update_task` both accept `time_estimate` (integer, minutes). Pass `0` or `null` to clear.
- **Briefings**: `morning_briefing` returns a `capacity` object summed across overdue and due-today workable tasks:
  ```json
  {
    "capacity": {
      "estimated_minutes": 270,
      "tasks_with_estimate": 5,
      "tasks_without_estimate": 9
    }
  }
  ```
- All task-fetch tools (`get_overdue_tasks`, `get_todays_tasks`, `morning_briefing`, `afternoon_briefing`) include `time_estimate` in their output.

## Smarter Briefings — Reading Tasks Excluded

Reading-lane tasks (`task_type: reading`) now stay out of operational briefing outputs by default.

- `morning_briefing`, `afternoon_briefing`, and `get_overdue_tasks` exclude `task_type = 'reading'` from overdue, due-today, and still-active lists.
- All compact SELECT outputs now include `task_type` and `tags` so agents can filter any edge cases that slip through.
- This fixes a recurring issue where agents would surface "Read: Marketing Toolkit" or "Patreon Quips" as overdue action items in daily briefings.

## Event Auto-Complete

Timed events on the calendar now close themselves out automatically.

**Auto-complete logic** (runs on every today-view load):
- Events with a `due_date` in the past are marked done.
- Events with `due_date` today and an `event_time` set are marked done once `end_time` (or `event_time + 1 hour`) has passed.
- All-day events (no `event_time`) are left alone — use the manual button.

**Manual done button**: a `✓` button now appears on every event card. Click it to dismiss immediately. Turns green on hover.

Together these mean you never have to manually clean up your event list at the end of the day.
