## Highlights

**The Linux server bootstrap can install or update to a release tag or exact commit, not only a branch.**

- Customer nodes are pinned to a release (`QALATRA_REF`), so bootstrap has to accept a tag or a
  full commit SHA. Before, an existing checkout ran `checkout REF` + `reset --hard origin/REF`,
  which fails for a tag the checkout hasn't fetched yet, and a fresh clone used `--branch`, which
  refuses a commit SHA.
- Bootstrap now fetches the ref and checks it out: a branch stays a branch, and a tag or commit is
  checked out detached. Re-running bootstrap against an existing node with a tag pin now works.

## Verification

- `bash -n scripts/bootstrap-linux-server.sh` passes.
- The fetch-and-checkout logic was run against a clone of this repo: a fresh install from a
  release tag, an existing checkout moved to a tag it had not fetched, a full commit SHA, and a
  branch all resolve; a short SHA is refused with the script's error message.
