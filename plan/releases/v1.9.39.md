## Highlights

**Agent timeouts no longer depend on Qalatra Server's event loop.** The wall-clock and optional idle
timeouts previously used `setTimeout` on the same loop they were expected to protect. If that loop
froze, neither callback could execute; a nominal 60-minute deadline could be delayed indefinitely.
Each running agent now gets a small worker-thread watchdog with an independent event loop. It owns
both deadlines and kills the agent's complete process group itself, including child test/build/tool
processes (`taskkill /T /F` on Windows).

The watchdog records whether the wall-clock or idle limit fired in shared atomic memory before the
kill. When the server loop resumes, the ordinary close handler can therefore persist `timed_out`,
`terminated_by = 'timeout'`, partial output, and the resumable session without depending on IPC event
ordering. If a watchdog cannot be created, Qalatra stops the job rather than allowing it to run
without its configured safety boundary. The 60-minute default and opt-in idle policy are unchanged.

**Agent slice isolation now fails safe when fleet configuration is absent.** Qalatra only launches
an agent into `qalatra-agents.slice` when that slice has a finite `MemoryMax`. A missing or unbounded
slice now leaves the agent in the server's existing capped cgroup instead of moving it into an
implicitly-created, unlimited slice. The check runs for every launch, so installing or removing the
fleet unit takes effect on the next job without restarting Qalatra.

**Long-lived AI context is bounded at its write funnel.** `ai_context` remains append-only, newest
last, but now retains the newest 50 entries / 8,000 characters and leaves a visible count of trimmed
entries. This complements field-projected reads by bounding callers that legitimately request the
field. Tool descriptions now consistently document append order rather than incorrectly instructing
agents that notes were prepended.

**Release-audit dependencies were refreshed.** The UI lock now resolves patched versions of
`@humanfs/node` and `browserslist`; compatible mobile patch releases update Expo Metro and
`browserslist`. The three remaining mobile advisories are the existing narrowly documented
exceptions in `scripts/audit-mobile.mjs`, and this release publishes no mobile artifact.

## Verification

The watchdog regression test deliberately blocks Qalatra's main JavaScript event loop beyond both a
wall-clock deadline and an idle deadline. In both cases the independent watchdog kills the child and
the shared state identifies the correct timeout while a control timer on the blocked loop remains
unable to fire. The test also verifies that output activity resets the idle deadline and cancellation
does not kill a completed job. It runs in the server CI and release gate.

The existing server tests continue to cover process-tree cleanup, resumable timed-out sessions,
bounded output consumers, field projection, and AI-context trimming. See
`plan/FLEET_HANDOFF_V1.9.39.md` for the canary, fleet rollout, alerting follow-up, and per-box slice
verification required after this tag is published.
