## Highlights

**Hosted account and entitlement foundation.** The shared client now supports qalatra.com login,
two-factor completion, secure native token storage, session-revocation recovery, and Connect/Cloud
seat checks. Hosted web builds can enable the gate explicitly; the free Electron build remains
ungated. The Expo client presents dedicated login, 2FA, unlicensed, and retryable service-error
states before backend onboarding.

**Secure Fleet bootstrap credentials.** Headless servers can accept a caller-supplied
`QALATRA_BOOTSTRAP_TOKEN` on first start, allowing Fleet to provision the same derived per-node
credential that it gives the control plane. The raw full-access token is no longer printed to
service logs.

## Release process

- Release tags must now match `package.json` and include checked-in curated notes under
  `plan/releases/`; missing notes fail the workflow instead of falling back to raw commit subjects.
- Every tag runs the full pre-publish gate before platform packaging: shared and mobile typechecks,
  account/auth/output-rule tests, server smoke coverage, import verification, UI lint, and a
  production UI build.
- Repaired `plan/EVOLUTION.md` so the v1.9.22–v1.9.34 history maps continuously to actual tags and
  restores four previously omitted security/API releases.

## Security maintenance

- Updated Electron, DOMPurify, js-yaml, Hono, fast-uri, ip-address, nanoid, brace-expansion, and
  their affected dependency paths to patched releases. Root and web audits are clean, and the
  shipped Markdown editor bundle was rebuilt with the patched sanitizer.
- Updated Expo 56 and its compatible transitive packages. Metro still carries two high-severity
  infinite-loop advisories through `image-size`; no patched `image-size` version exists. The parser
  is build-only and receives trusted repository assets, so the mobile gate has a narrow temporary
  exception for those two advisory IDs while continuing to reject every other finding.

## Notes

The hosted-web deployment and signed native mobile builds still require production CORS, real-device,
and app-store validation. These source changes do not add an account gate to the free desktop app.
