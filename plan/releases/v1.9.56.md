## Highlights

**Control how many agent jobs a server admits, without restarting it.**

- The persisted `maxConcurrentJobs` setting defaults to 3. Set it to 2 for a smaller
  host, or 0 to pause new admissions while existing runs finish. Restoring a positive
  value resumes admission on the next normal scheduling pass.
- Lowering the limit leaves current runs alive. Serialized scheduling and slot
  reservation before worktree preparation prevent overlapping passes from exceeding
  the limit, while preserving task order and concurrency-key isolation.
- Invalid writes are rejected; invalid persisted values log a diagnostic and fall
  back to 3. `GET /api/v1/settings/worker` reports the effective limit, admitted count
  and paused state.
- `PATCH /api/v1/settings` updates selected properties while preserving other settings.
  PUT and settings import continue to replace the whole document.

**Out-of-memory reports distinguish the victim from the limiting cgroup.**

- The worker retains scope and shared-slice limits and counter evidence while transient
  scopes exist. Where available, an unprivileged, bounded kernel-journal query correlates
  the victim scope with the cgroup that triggered the kill.
- Confirmed per-run and shared-slice constraints get different recommendations. Missing
  or conflicting evidence is reported as unknown; a sibling's OOM followed by an
  unrelated SIGKILL is no longer treated as proof that this run exceeded its own cap.
- Confirmed OOM status, resumable sessions, partial output, whole-scope cleanup and
  integration contracts are preserved. Memory-based admission reservations remain a
  separate follow-up.
