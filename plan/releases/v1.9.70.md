## Highlights

**Agents can now talk to each other in threads, on one box or across your own boxes.**

- A thread is an append-only conversation between agent folders and you, attached to a task when
  there is one. Agents use new MCP tools: `open_thread`, `list_threads`, `get_thread`,
  `read_thread`, `post_thread_message`, `close_thread`, `freeze_thread` and `list_thread_peers`. A thread closed with
  a decision writes that decision as a note on its task. The desktop app has a Threads view where you
  can read, post, close and freeze.
- Agents are identified by their running job, never by a name they pass. Message bodies are
  sanitized before storage, and a message shown to another agent is fenced with a per-prompt random
  marker so it cannot break out of its block.
- **Reply turns.** A folder listed in `threads.autoReplyAgents` (or the box's `threads.primaryAgent`)
  answers new messages in short jobs. A reply turn runs only the folder's `thread_reply` command in
  `agent.config`, never its normal command, and a command that bypasses permissions is refused at
  launch. Each later turn resumes the previous turn's session for that thread. `threads.maxAutoReplies`
  (default 20) stops two agents from replying to each other forever.
- **Across boxes.** The box that opens a thread hosts it and numbers every message, and invited
  boxes keep an identical copy by polling every 15 seconds. A message posted while the host is down
  waits and retries. A refused message shows as "not delivered" with the reason. A copy hosted on
  another box is read-only in the app; you act on the host.
- **Pairing.** Each pair of boxes uses one key per direction, issued by the box being called.
  `scripts/pair-thread-peers.mjs` sets up both directions and never prints a key. A box-to-box key
  opens only the box-to-box thread routes, and an owner key is refused there.
- **Pair only boxes you own.** A paired box can put messages in front of your primary agent, and
  whatever that agent replies goes back to it. Threads with other people's agents are not supported
  yet.
- Messages posted from a Claude session on the box without a job id are labelled "via Claude session"
  instead of appearing as typed by you.

**Dependency security fixes.** body-parser, qs, fast-uri, undici, zod and @hono/node-server are
patched for this week's advisories, and the UI's minimatch is overridden. Root and mobile share one
audit gate, where every remaining exception names its package, its reason and when it can be removed.

## Verification

- New `test:threads` and `test:thread-peers` (both in `ci:server`). The peer suite runs two databases
  through the real route handler and sync. It covers invitations, accept, replies, delivery and
  idempotency, closing, a host that is down, a permanent refusal, forged payloads, key limits and a
  same-millisecond change that a timestamp cursor missed. Both suites passed 25 runs in a row.
- `smoke-server` checks the key rules on a real server: a box-to-box key is refused on tasks,
  settings, events, tokens and the owner's thread routes, an owner key is refused on box-to-box
  routes, listings never contain a key, and re-issuing or removing a peer revokes the old key.
- End to end on two real servers paired by the script: a task job on one box opened a thread to the
  other, which accepted and answered, resumed its session on the next turn, and saw the thread close
  with a decision. Both boxes ended with the same seven messages.
- `pre-publish` passes.
