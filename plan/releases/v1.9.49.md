## Highlights

**A bound folder's FlightDesk identity now reaches the job, not just the poller.** The folder's
`.flightdeskrc` was consulted only when Qalatra polled for dispatches. The job it then launched in
that folder never saw it, and the `flightdesk` CLI inside the job finds a key by walking up from
its working directory. An agent whose first act is `cd` to its repo root — above the agent
folder — walked past the folder's credential and landed on `~/.flightdeskrc`, so every
`turn end`, `plan submit` and `dispatch list` from inside the repo ran as the box owner instead of
the folder's agent user. Polling kept the promise that the credential *is* the folder's identity;
the job silently broke it.

- **`FLIGHTDESK_API_KEY` / `FLIGHTDESK_API_URL` are injected from the folder's rc on every job that
  runs in a bound folder** — heartbeats and manual runs included, since the pipeline heartbeat is
  exactly the job that carries no dispatch metadata. The CLI honours these over any rc it would
  find by walking up from its cwd, so the agent's working directory no longer matters. Not gated
  on the integration kill switch: a folder that is bound but not polled still has one identity.
- **The rc wins over `agent.config.env` and `settings.agentEnv`.** The file is the binding; a stale
  `agent.config` committed in a client repo must not be able to re-identify a folder.
- **A dispatch payload can no longer set those names.** `external_meta.env` refuses
  `FLIGHTDESK_API_KEY` and `FLIGHTDESK_API_URL` alongside the `QALATRA_*` prefix, closing the
  hole where an orchestrator could swap a job's identity from outside the box.
- Unbinding stays live: deleting the rc means the next launch injects nothing, no restart.

Additive, no migration, no new settings. Nothing on the boxes needs to change — the rc files are
already there.

## Verification

Nine new cases in `npm run test:flightdesk-dispatch` cover the rc read, the URL default, the
no-rc folder, precedence over `agent.config.env`, the heartbeat (no `external_meta`) path, the
refused external override, and rc deletion between launches; the existing suite still passes.
On-box check on Shi after the updater rolls this: from inside the repo checkout, *as a Qalatra
job*, `flightdesk whoami` must report the Shi agent user and `env | grep ^FLIGHTDESK_API_` must
show both variables.
