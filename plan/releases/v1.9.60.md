## Highlights

**A server restart no longer turns running agent jobs into failed turns.**

- Updates, deploys, secret rotations and crashes used to kill every live agent run and mark it
  orphaned. FlightDesk then recorded FAILED turns while the jobs' cloud sessions kept working, and
  flagged the sessions' later reports as stale.
- Agent output now goes to per-job files under the data directory instead of pipes into the
  server, and each run records its own exit status. Shutting the server down leaves runs going.
- On startup, Qalatra checks each job left running before reporting anything. A run that is still
  alive is picked up again, keeping its concurrency slot and its original timeout. A run that ended
  while the server was down is finished from its recorded exit as done or failed. Only a run whose
  process is gone is reported orphaned, and it keeps its session id and partial output, so
  FlightDesk gets `orphaned` with `resumable: true` and the task's next job resumes that session.
- A run is only picked up again when both its pid and the process start time match, so a pid
  reused after a reboot is never treated as an agent.
- Set `killAgentsOnShutdown: true` in settings to keep the old behaviour. On the desktop, quitting
  the app now leaves running agents going until the next launch picks them up. Windows runs are
  still stopped with the server.

**Linux upgrades restart the server, and headless tunnel login fails fast.**

- `install-linux-server.sh` now restarts an already-running server after an upgrade, instead of
  leaving the old process serving the previous version over the new checkout.
- `install-cloudflare-tunnel.sh` fails at once with instructions when there is no terminal for
  `cloudflared tunnel login`, instead of waiting ten minutes for a browser. Set
  `QALATRA_TUNNEL_LOGIN=1` to force the attempt.

**Pipeline agent configuration.**

- The bundled pipeline agent runs each task in its own worktree with 2G/3G per-run memory, and its
  merge rule treats green CI as the approval now that FlightDesk no longer dispatches a verifier.

## Verification

- New `test:agent-restart` (added to `ci:server`): one process launches five jobs and shuts down
  the way the server does, then a second process reconciles them. It checks a live run picked up
  again and finished done, a run that ended while down, a run timed out against its original
  deadline, and two orphans, one with its session id and partial output.
- The worker lifecycle, job scheduler, watchdog, memory, output-rule, command-template, FlightDesk
  dispatch, job concurrency and worktree suites pass, as does the server smoke test.
- The systemd scope path has not yet run on a Linux box.
