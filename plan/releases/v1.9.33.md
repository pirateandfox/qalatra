## Highlights

**Agent output rules work again.** `output_rules` in `agent.config` silently stopped running when
agent job execution moved to the headless server in May. Rules now evaluate every successful job
against its normalized result: stdout for command/template jobs and the parsed result for prompt
agents. When output contains multiple matches, the final match wins, so an upstream Qalatra ID
cannot outrank the downstream ID the rule is intended to capture. Invalid rules are logged without
blocking later rules or job completion.

**Reorderable instances.** Settings → Instances now supports drag-and-drop and accessible up/down
controls. The saved order drives the top-bar instance switcher immediately, and editing an instance
preserves its position instead of moving it to the end.

## Fixed

- Added `orphaned` to the shared `AgentJob.status` and `Task.agent_job_status` type unions,
  completing the type support for the restart-interruption status introduced in v1.9.32.

## Verification

Added regression coverage for command output, prompt-agent JSON output, final-match selection,
malformed-rule isolation, persisted links, and failed-job exclusion.
