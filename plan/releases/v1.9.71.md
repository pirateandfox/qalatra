## Highlights

**Thread reply turns can post under a reply profile without a shell.**

- The reply prompt told the agent to read `QALATRA_JOB_ID` from its environment, but the documented
  `thread_reply` profile allows no shell commands. The agent posted without a job id, which counts as
  the human. On a thread hosted on another box that is refused ("This thread is hosted on Shi; the
  human posts there"), so the reply was lost.
- The reply prompt now states the turn's own `job_id`. Qalatra chooses the reply job's id before
  creating the job, so the prompt and the job always match, and orchestrators still cannot choose
  job ids. The prompt says to use this turn's id, not one from an earlier turn of the resumed session.
- The refusal on a thread hosted elsewhere now says that an agent job must pass its `job_id`.
- A reply turn that already ended without posting is not retried by itself. The next message in that
  thread starts a turn that can post.

**node-forge 1.4.3 in mobile build tooling.** A moderate advisory covering node-forge 1.4.2 and
earlier was published after v1.9.70. It reaches mobile through Expo's CLI and code-signing
certificates. Only the mobile lockfile changes, and the desktop app does not use node-forge.
