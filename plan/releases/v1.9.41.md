## Highlights

**Agent timeouts now kill the complete Linux systemd scope.** Claude Code can start Bash tools in
new process groups, allowing them to survive the prior negative-pid process-group kill. A leaked
tool could remain charged to `qalatra-agents.slice`, hold the shared slice above `MemoryHigh`, and
silently throttle every later agent until each reached its configured timeout.

Linux launches now use deterministic `qalatra-agent-<job-id>.scope` names. The independent timeout
watchdog kills every process in that scope through systemd, reaching children that call `setsid`,
reparent, or double-fork even if the original agent pid has disappeared. Server shutdown and normal
job completion use the same boundary so daemonized leftovers cannot survive either path. Existing
process-group and Windows process-tree cleanup remain as portable fallbacks.

**Every agent scope has its own memory controls.** Each transient scope receives `MemoryHigh=1G`,
`MemoryMax=2G`, and `OOMPolicy=kill`. Reclaim pressure is applied to the individual run before the
shared slice, while an agent that reaches the hard ceiling has its entire scope terminated.

## Verification

The Linux regression starts a `setsid sleep` whose process group differs from its tracked agent,
fires the watchdog, and verifies that both the escaped child and transient scope disappear. A live
Drift verification confirmed the distinct process groups, both memory thresholds, `OOMPolicy=kill`,
complete scope termination, and `--collect` cleanup.

The full pre-publish gate passed locally: root and UI audits, the documented mobile audit, import
checks, shared and mobile typechecks, account and server test suites, headless server smoke test, UI
build, and UI lint. UI lint reports the same 33 pre-existing warnings and no errors.
