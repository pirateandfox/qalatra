## Highlights

**A turn that ends while its own work is still running is reported as failed, not done.**

- An agent could start a long command in the background (a build, a test run), end its turn while
  saying it would wait, and exit cleanly. Qalatra then cleaned up the run, which killed that
  command, and still recorded the job as `done`. An orchestrator saw a clean turn whose work had
  been thrown away.
- On a clean exit, Qalatra now looks in the run's scope, before cleaning it up, for the agent's own
  shell commands that are still running. If any are, the job is `failed` with
  `terminated_by = exited_with_children`. The result lists the commands that were killed, at the
  end, where FlightDesk's diagnostics tail keeps them. The session stays resumable.
- Only the agent's own tool commands count. MCP servers that outlive the agent for a moment do not.
  On a busy box about half of all runs still have one of those in the scope when cleanup starts,
  and all of those runs remain `done`.
- Detection covers Claude Code's Bash tool. Background work from other runtimes is still cleaned
  up as before, without the new outcome.

## Verification

- New `test:agent-leftovers` (in `ci:server`): tool commands are found and their quoted command

  grace period is clean, and the notice fits the 4096-character tail and carries no OOM wording.
- Checked against a real systemd scope on a Linux box: a backgrounded tool command was reported
  and its plain child process was not counted separately.
