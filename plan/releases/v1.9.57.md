## Highlights

**Claude Bridge errors are routed by their code, and page text no longer leaks to FlightDesk.**

- Claude Bridge 0.1.19 prefixes every error with `[CODE]` and a `Details` block. Session ops
  now route on that code: only `SESSION_NOT_FOUND` / `INVALID_SESSION_ID` mean the session is
  gone. Pop-ups (`PAGE_UNREADABLE`) and "Create PR button not found"-style failures are no
  longer misreported as "unknown session".
- `NOT_AUTHENTICATED`, a missing or crashed tab, and other recoverable unreadable-page states
  report as `dependency_down`, so FlightDesk treats them as the box being unavailable.
- Diagnostics sent to FlightDesk lead with the error code and carry only allow-listed fields.
  Scraped page body and dialog text are withheld.
- `state` passes through a sanitized `pageIssue` and `recovered`; `inject`/`archive` pass
  `recovered`. Archiving an already-archived session now counts as done.

**Non-Claude agent commands work without an explicit runtime.**

- When `agent.config` sets no `runtime`, Qalatra infers it from the command's binary: `codex`
  gets the Codex adapter and `claude` gets Claude. That includes `defaultAgentCommand`, so
  `codex --yolo` no longer gets Claude's prompt flags appended.
- Unrecognised binaries, such as wrapper scripts, keep the Claude runtime as before and log a
  warning pointing at `"runtime"`. Settings shows the same hint.
- An `agent.config` that exists but can't be read or parsed is now logged with its path by
  both the job launcher and the agent scan. Previously it was silently ignored. Missing configs
  still fall back to the default command, as intended.

**Agent scans are consistent and clean up after themselves.**

- The MCP `rescan_capabilities` tool and the server scan now share one write path. It
  records `worktrees` and `concurrency_key`, and updates agents and capabilities in a
  single transaction.
- Folders removed from disk are pruned: the agent row is deleted and the capability marked
  inactive. This only covers folders under the scanned root, so a narrow rescan never touches
  anything outside it.
- `active` is documented as controlling visibility only.

**Cleanup:** removed an unused Box Web refresh hook. The Tools tab reconnects with a fresh
session instead.

## Verification

- Full pre-publish gate passed: dependency audits, type checks, account/server tests, UI
  production build and lint (existing warnings only), and Electron import/package checks.
- New session-ops and FlightDesk-dispatch tests cover each bridge error code, uncoded
  errors, Details containing "not found", and that page text never reaches the outbound
  payload.
- Runtime inference is covered in the command-template tests and end to end in the worker
  lifecycle test: unknown binary, explicit raw, codex, and an invalid agent.config.
- New scan tests in `test:job-concurrency` cover MCP/server parity, pruning, narrow rescans,
  reappearance, `active:false`, and rollback of both tables on mid-scan failure.
  `test:worktrees` and `test:flightdesk-dispatch` pass.
