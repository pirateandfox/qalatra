## Highlights

**The agent scan no longer falls back to the home folder.**

- With no folder configured, the scan used to walk the whole home folder. On a Mac that meant
  `~/Library/CloudStorage`, where a streaming Google Drive mount downloads every file it is asked
  about, so a fresh install could hang the agents list and the Terminal panel and register
  unrelated agents.
- The scan root is now `agentsRoot`, then `workspaceRoot`, then `terminalCwd`, with `~` expanded.
  With none set there is no scan, and Settings says so.
- The walk skips dot-folders, `node_modules`, `dist`, `.qalatra-worktrees`, cloud-storage mounts,
  `Library` directly under a home folder, system mounts and macOS package folders. It stops at a
  depth of 10, 50,000 folders or 60 seconds, and gives up on a folder that does not answer within
  10 seconds.
- A scan that stops early adds the agents it found and removes nothing. A complete scan also
  removes agents registered from outside the current root, so narrowing the root cleans up.
- Requests that arrive during a scan share it instead of starting their own.
- The Terminal panel loads sessions without waiting for the agent list, and the agent picker shows
  whether agents are still loading or failed to load.

**hono 4.13.19.** Patch release for two moderate advisories in hono, which the MCP SDK uses.

## Verification

- `test:agent-scan` covers the root order, `~` expansion, every skip, the depth, folder and
  unresponsive-folder limits, the no-root case (nothing read, nothing written), shared scans, and
  pruning only after a complete scan.
- On the dev Mac: no root returns an empty list in 9 ms; a whole-home scan stops at the folder cap
  in 3.7 s without reading under `Library`, `CloudStorage` or dot-folders; `~/IdeaProjects` scans
  22k folders and finds 105 agents in 1.2 s.
- `pre-publish` passes.
