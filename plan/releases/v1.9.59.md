## Highlights

**A long agent job for one task no longer holds every other task's FlightDesk relays.**

- FlightDesk session ops (rebase relays, CI-failure relays and verifier injects) used to wait
  while any job ran in the agent folder, even with per-task worktrees on. One task's
  45-minute codegen job could hold every other task's relays for its whole run.
- An op now waits only for a running job on the same task, a job with no task identity
  (heartbeat or manual run), or a job on the op's own session. An op that names no task still
  waits for any job in the folder. Job admission and concurrency keys are unchanged.
- This lets FlightDesk relay rebase injects into cloud sessions as soon as an auto-merge PR
  conflicts, instead of waiting behind unrelated work on the box.

**Dependency security updates.**

- The MCP SDK moves to 1.32.1. `proxy-addr`, `sharp`, `shell-quote`, `source-map-js` and
  `compression` are updated for advisories published this week. The mobile app keeps its four
  documented build-tooling exceptions.

## Verification

- Full pre-publish gate passed: dependency audits, type checks, account/server tests including
  the MCP lifecycle test on the new SDK, UI production build and lint (existing warnings only),
  and Electron import/package checks.
- New `test:flightdesk-dispatch` cases: task B's op runs while task A's job runs; task A's op is
  deferred; an op with no task is deferred; both run once A's job ends. The existing
  no-task-identity deferral case still passes, as do `test:job-concurrency` and `test:worktrees`.
